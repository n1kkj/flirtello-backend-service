## Заметки

### Реализация

Расширил команду `/me333` для отображения текущего `channel_id`.

**Изменения:**
- Добавлены импорты `Channel` и `select` из `sqlmodel`
- Добавлена логика получения `channel_id` через запрос к таблице `Channel` с использованием:
  - `active_char_id` (текущий активный персонаж)
  - `user.id` (ID пользователя)
  - `current_config_id_from_settings` (текущий config_id)
- Добавлено поле `channel_id` в JSON-ответ команды `/me333`

**Файлы изменены:**
- `src/telegram/handlers/commands/me.py`

**Логика:**
- Если `active_char_id` существует, выполняется запрос к базе данных для поиска соответствующего канала
- Если канал найден, его ID добавляется в ответ
- Если канал не найден или отсутствуют необходимые данные, `channel_id` будет `None`

### Исправление бага с NULL значениями

**Проблема:**
При первоначальной реализации код не находил каналы, когда `config_id` был `NULL` как в канале, так и в настройках пользователя. Это происходило из-за того, что:
1. Условие `if active_char_id and current_config_id_from_settings:` не выполнялось, если `config_id` отсутствовал в настройках
2. В SQL сравнение `NULL = NULL` возвращает `NULL` (не `TRUE`), поэтому условие `Channel.config_id == current_config_id_from_settings` не срабатывало для NULL значений

**Решение:**
- Убрана проверка `current_config_id_from_settings` из условия `if` (теперь проверяется только `active_char_id`)
- Добавлена правильная обработка NULL значений для `config_id`:
  - Если `current_config_id_from_settings` не `None`, используется сравнение на равенство
  - Если `current_config_id_from_settings` равен `None`, используется проверка `Channel.config_id.is_(None)`

**Проверено:**
- Для пользователя `c0471bd8-bc01-40c6-a834-dbb70143b59c` канал с `id=71135`, `char_id=10`, `config_id=NULL` теперь корректно находится

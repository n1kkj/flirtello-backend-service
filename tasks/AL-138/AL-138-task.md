# AL-138: Постпроцессинг сообщений от персонажа

## Требования из Asana

Постпроцессинг должен включать:
1. Управление длиной сообщения и стилем
2. Исправление форматирования для Telegram

### Правила длины сообщений

**Типы сообщений:**
- **Короткие**: 1 предложение, 3-15 слов (варьируется)
- **Средние**: 2 предложения, до 25 слов
- **Длинные**: 3 предложения, до 40 слов

### Правила по контексту

- **Начало общения/флирт** (safe/questionable): только короткие и средние сообщения
- **Сексуальные сцены** (nude/explicit): все 3 вида сообщений

### Правила чередования

- Не должно быть двух одинаковых типов сообщений подряд
- Количество слов в коротких сообщениях должно варьироваться (3, 5, 9, 12, 15 и т.д.)
- **Чередование**: рандомный выбор типа сообщения из доступных

## Заметки

### Определение контекста диалога

**Подход:**
- Использовать логику определения rating из `context-images-microservice`
- Анализировать последние 10 сообщений диалога
- Определять rating: `safe`, `questionable`, `nude`, `explicit`
- Использовать промпт из `flirtello-chats/src/infrastructure/services/llm/openai_chat_analyzer.py` - `INFER_SCENE_PROMPT_TEMPLATE`

**Маппинг контекста:**
- `safe` / `questionable` → начало общения/флирт (только короткие и средние)
- `nude` / `explicit` → сексуальные сцены (все 3 вида)

### Изменение длины сообщения

**Подход:**
- Использовать LLM для преобразования сообщений в нужный размер
- **3 промпта для преобразования** (не зависят от типа сцены):
  - `make_short` - сделать сообщение коротким (1 предложение, 3-15 слов)
  - `make_medium` - сделать сообщение средним (2 предложения, до 25 слов)
  - `make_big` - сделать сообщение длинным (3 предложения, до 40 слов)
- **Тип сцены используется для выбора промпта** (какой размер использовать):
  - `safe/questionable` → только `make_short` и `make_medium` (короткие и средние)
  - `nude/explicit` → все три: `make_short`, `make_medium`, `make_big` (все размеры)
- **Важно для ВСЕХ сцен и ВСЕХ размеров**: сделать сообщения разнообразными по структуре - избегать одинаковых шаблонов, чтобы они не читались одинаково визуально и ритмически. Даже если сообщение большое, оно должно быть "большим по-разному" (разная структура, разные паттерны предложений, разный ритм)

**Эксперименты:**
- Взять несколько длинных сообщений из БД (уже есть в `test_messages/`)
- Протестировать несколько LLM моделей
- Протестировать 3 промпта для укорачивания с разными типами сцен
- Создать тулзу для экспериментов: сообщения × промпты × LLM × типы сцен
- Выбрать лучшую комбинацию

**Тулза для экспериментов:**

**Вариация в коротких сообщениях:**

### Чередование типов сообщений

- Рандомный выбор типа сообщения из доступных (с учетом контекста)
- Если контекст ограничивает (только короткие/средние), выбирать рандомно из доступных

- Нужно исправить форматирование по правилам Telegram MarkdownV2

**Решение:**
- Восстановить правильный Telegram MarkdownV2 формат
- Правила можно найти на странице Telegram
- Убедиться, что постпроцессинг не ломает форматирование
